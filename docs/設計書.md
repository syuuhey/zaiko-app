## §1 目的と範囲

小売店の業務モデル(発注/売上報告/月次の数字の確認/レジ・接客/レジ締め)を自店2店舗(アイスタベタイ/DONUT TABETAI、what's?)に当てはめ、zaiko-app に足りない部分だけを追加する。

**作るもの**
1. 発注: 低在庫から発注候補を出し、発注数を決めて記録し、発注済/入荷済を管理する
2. レジ金: Airレジの入出金履歴を取り込み、経費か現金移動かを仕分ける(単体HTML「レジ金仕分けツール」の統合)
3. 財務の状況: レジ内現金・預入・過不足と、売上/経費/営業利益の月次推移を1画面で見る

**作らないもの**
- 仕入先への発注送信の自動化(電話・LINE・サイトで人が行う)
- 会計(商品読取・代金受取)、返品・交換、お取り寄せ … Airレジの担当範囲
- 本部への売上報告 … 本部が無い。ダッシュボードで代替済み
- 税務申告、会計ソフトへの仕訳連携(仕訳CSV出力は移植しない。単体HTMLは残す)

## §3 フェーズ1: 発注

### 画面
- `/dashboard/orders`(店長ログイン必須。既存の `MonthStoreNav` の店舗切替を使う)
- スタッフ用の在庫画面(`app/page.tsx`)は「要発注」表示のまま。発注済の商品にだけ「発注済」バッジを足す

### 動き
1. **発注候補**: `min_stock > 0 かつ stock <= min_stock` の商品を仕入先(`items.supplier`)ごとにまとめて表示
   - 推奨数 = `max(ideal_stock - stock, 0)`。`ideal_stock` が 0 の商品は推奨数を空欄にして手入力させる
   - **未入荷の発注(状態=発注済)がある商品は候補に出さない**(二重発注防止)
2. **発注を記録**: 数量を確認・修正して「発注済にする」。状態は `発注済`。発注日時・発注者名を残す
   - 候補に無い商品も手動で追加できる
3. **入荷**: 「入荷済にする」で状態を `入荷済` にし、入荷数を在庫に加算、`stock_logs` に記録(note=`入荷`)
   - 状態更新・在庫加算・ログ記録は **1つのDB関数(RPC)で原子的に**行う。クライアントから3回に分けて更新しない
   - 入荷数は発注数と違ってよい(入荷数を入力)
4. **取消**: 発注済のものだけ取消できる。入荷済は取消不可(在庫を直すときは在庫画面から)

### 状態遷移
```
(候補) ──発注済にする──▶ 発注済 ──入荷済にする──▶ 入荷済
                           └──取消──▶ 取消
```

### やらないこと
- 発注を `expenses`(経費)に自動計上しない。仕入はレシート・請求ベースで従来どおり計上する(二重計上防止)
- 仕入先への送信、LINE通知の新設

## §4 フェーズ2: レジ金の入出金取込と仕分け

移植元: `~/在庫管理表/レジ金仕分け/index.html`(ロジックの正。読むだけで編集しない)

### 画面
- `/dashboard/cash`(店長ログイン必須)

### 取込
- Airレジ「入出金履歴CSV」(Shift-JIS。UTF-8保存し直しにも対応)。列: 店舗番号/店舗名/レジID/レジ担当者ID/レジ担当者名/営業日/取引日時/入出金タイプ/入出金額/コメント
- Airレジ「精算履歴」は画面コピペの貼り付けで取込(CSV出力が無いため)
- 同じ行を二度取り込んでも重複しない(§6 の一意キー)
- 取込先の店舗は画面で選んだ店舗。CSVの店舗番号と食い違う場合は取込を止めて警告する

### 仕分けルール(単体HTMLと同じ)
- 入出金タイプが **預入金・つり銭準備金(釣銭準備金)** → `現金移動`。経費にしない
- 入出金タイプが **過不足** → `現金過不足`
- それ以外の出金 → コメントのキーワードで科目を自動判定。該当なしは `未分類`
- 科目を手で直したら、そのコメントは次回から同じ科目(辞書に記憶)
- 科目は `expense_categories` を使う(新しい科目マスタを作らない)

### 経費への計上
- **自動では計上しない。** 行ごと(または選択した行をまとめて)「経費に登録」を人が押す
- 登録時、同じ店舗・同じ日・同じ金額の経費が既にあれば警告を出す(LINEレシートbotとの二重計上防止)
- 登録済みの行は `expenses` の行とひも付け、再登録できないようにする

### 読み方(実データで検算済み。変えない)
- 精算金額 = その日の預入金を引く前のレジ内現金。翌日繰越 = 精算金額 − 同日の預入金
- 現金売上(推定) = 締め残高 −(前日繰越 − 出金・つり銭)
- 現金売上 0 の日はキャッシュレスのみの日で正常。エラーにしない

## §5 フェーズ3: 財務の状況

### 画面
- `/dashboard/cash` の上部、またはダッシュボードのサマリー(`/dashboard`)に追加

### 表示
1. **日別の現金**: 前日繰越 / 現金売上(推定) / 出金・つり銭 / 預入金 / 締め残高 / 過不足
2. **月のまとめ**: 月末のレジ内現金、預入金の合計、過不足の合計、未分類の件数、経費未登録の件数
3. **突合**: Airレジ由来の預入・過不足と、レジ締め報告(`register_closings.deposit` / `over_short`)が同じ日で食い違えば赤で表示
4. **推移**: 直近6か月の税抜き売上・経費合計・営業利益(`computePnl()` を月ごとに呼ぶ。計算を複製しない)

### やらないこと
- 銀行口座残高・借入・未払金の管理(貸借対照表は作らない)

## §6 DB変更(0009 は承認済み / 0010 は未承認)

### 0009 発注
```sql
create table if not exists purchase_orders (
  id uuid primary key default gen_random_uuid(),
  store_id uuid not null references stores(id),
  item_id uuid not null references items(id),
  supplier text not null default '',
  quantity integer not null check (quantity > 0),
  received_quantity integer check (received_quantity >= 0),
  status text not null default '発注済' check (status in ('発注済', '入荷済', '取消')),
  ordered_by text not null default '',
  ordered_at timestamptz not null default now(),
  received_at timestamptz,
  note text not null default ''
);
create index if not exists purchase_orders_store_status_idx on purchase_orders(store_id, status);
-- 同じ商品に未入荷の発注は1件まで(二重発注防止)
create unique index if not exists purchase_orders_open_item_idx
  on purchase_orders(item_id) where status = '発注済';
-- + RLS(店長のみ select/insert/update)
-- + 関数 receive_purchase_order(order_id, received_quantity, checked_by):
--   発注を入荷済に更新 → items.stock を加算 → stock_logs に記録、を1トランザクションで行う
```
スタッフ画面の「発注済」バッジは anon では `purchase_orders` を読めないため、**発注中の item_id だけを返す関数**(security definer)を1つ用意する。金額・数量は返さない。

### 0010 レジ金
```sql
create table if not exists cash_movements (
  id uuid primary key default gen_random_uuid(),
  store_id uuid not null references stores(id),
  business_date date not null,
  occurred_at timestamptz not null,
  movement_type text not null,          -- Airレジの入出金タイプそのまま
  amount integer not null,              -- 元データの符号のまま
  comment text not null default '',
  kind text not null default '未分類' check (kind in ('経費', '現金移動', '現金過不足', '未分類')),
  category_id uuid references expense_categories(id),
  expense_id uuid references expenses(id),   -- 経費に登録したらひも付け
  created_at timestamptz default now(),
  unique (store_id, occurred_at, movement_type, amount, comment)
);
create table if not exists cash_settlements (
  store_id uuid not null references stores(id),
  business_date date not null,
  amount integer not null,              -- 精算金額(預入金を引く前のレジ内現金)
  diff integer,                         -- 過不足
  primary key (store_id, business_date)
);
create table if not exists cash_comment_rules (
  comment text primary key,             -- 手で直したコメント → 科目の記憶
  category_id uuid not null references expense_categories(id)
);
-- + RLS(3テーブルとも店長のみ)
```
`expenses.source` の CHECK 制約に `'cash_csv'` を追加する(現在は `'manual'`, `'line_ocr'` のみ)。既存行には影響しない。
