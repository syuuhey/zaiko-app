## §1 目的と範囲

**目的: 毎日開いて、数回のタップで終わる在庫アプリにする。** 開いたら「今日やること」が出て、入力は最小限で済むこと。

アプリは 2026年7月から使われていない(§2)。機能を足すより、在庫・発注・廃棄を使いやすくすることを優先する。

**作るもの**
- 画面の全面作り直し(スマホ前提・下タブ4つ)。見た目・画面遷移・URL は変えてよい
- 在庫のまとめて保存、発注点・適正在庫・仕入先の一括設定
- 発注画面のログイン不要化

**変えないもの**
- 登録済みの商品データ(86件)。**再入力させない。テーブルもデータもそのまま使う**
- 発注のDBと処理(`purchase_orders`、`receive_purchase_order`)。画面だけ載せ替える
- 経営ダッシュボード(`/dashboard` 配下)の中身。メニューから外すだけで削除しない

**作らないもの**
- レジ金の入出金取込、財務の状況 … 保留
- 仕入先への発注送信、LINE通知・Cron の追加
- 会計・返品・お取り寄せ(Airレジの範囲)

## §3 画面構成と共通ルール

### 画面一覧

| URL | 画面 | 元 |
|---|---|---|
| `/` | ホーム(今日やること) | 新規。旧 `/` の在庫一覧は `/stock` へ |
| `/stock` | 在庫チェック | 旧 `/` |
| `/orders` | 発注 | 旧 `/dashboard/orders` |
| `/waste` | 廃棄 | 既存。見た目だけ合わせる |
| `/more` | その他(メニュー) | 新規 |
| `/items` | 商品管理 | 旧 `/admin` |
| `/items/setup` | 一括設定 | 新規 |
| `/history` | 履歴 | 既存。見た目だけ合わせる |
| `/dashboard/*` | 経営ダッシュボード | 既存のまま。`/more` からだけ行ける |

旧URLは転送する: `/admin` → `/items`、`/dashboard/orders` → `/orders`。

### 共通ルール
- **下タブ4つ**: ホーム / 在庫 / 発注 / その他。全画面(`/dashboard` 配下を除く)に出す
- **店舗切替**は画面上部(既存 `StoreSwitcher`)。選んだ店舗は端末に記憶し、次回もその店舗で開く
- **担当者名**は最初の1回だけ入力し、端末に記憶する(localStorage)。在庫・発注・廃棄で共通に使う。その他から変更できる
- スマホ幅を基準にする(PCでは中央寄せの1カラム)。タップする要素は高さ 44px 以上
- 色は白黒を基本にし、色を使うのは状態だけ(要対応=橙、完了=緑、進行中=青)
- 数値入力は `type="text" inputMode="numeric"` + フォーカス時全選択
- 保存の成功・失敗は必ず画面に出す。失敗を黙って捨てない
- 商品が 0 件の店舗では、どの画面でも「商品を登録する」ボタン(→ `/items`)を出す。**what's? はいつでも登録を始められる状態にする**

## §4 各画面の仕様

### `/` ホーム
選択中の店舗について、次のカードを上から並べる。カードを押すと該当画面へ。

| カード | 表示 | 行き先 |
|---|---|---|
| 発注が必要 | 件数と、仕入先ごとの内訳(上位2件+ほか) | `/orders` |
| 入荷待ち | 発注済で未入荷の件数 | `/orders` |
| 在庫チェック | 最後に在庫を記録してからの日数(当日は「今日 チェック済み」) | `/stock` |
| 廃棄 | 今日(営業日)の記録があるか | `/waste` |
| 設定が足りない商品 | 発注点が未設定の件数。0 件なら出さない | `/items/setup` |

- 「発注が必要」= `min_stock > 0 かつ stock <= min_stock` で、未入荷の発注が無い商品
- 営業日の考え方は廃棄画面と同じ(0:00〜4:59 は前日扱い)。同じ関数を使い、複製しない
- 件数 0 のカードは「なし」と表示し、色をつけない

### `/stock` 在庫チェック
- カテゴリ(備品 / 食料品)を上部で切替。件数を添える
- 1行 = 商品名、単位、発注点、現在の在庫数、＋−ボタン。数字を押すと直接入力できる
- 変更した行は色を変える。**その場では保存しない**
- 下部に固定の「変更した n 件をまとめて保存」。押すと変更行だけ保存し、1件ごとに `stock_logs` に記録する
- 一部が失敗したら、成功分は確定し、失敗した行を変更状態のまま残して理由を出す
- 未保存の変更があるまま別の画面へ移ろうとしたら確認を出す
- 発注点以下の行に「要発注」、発注済で未入荷の行に「発注済」を出す

### `/orders` 発注
- **発注候補**: 仕入先ごとにまとめる。数量は `max(ideal_stock - stock, 0)` を初期値にし、＋−で直す。`ideal_stock` が 0 の商品は初期値 1
- 仕入先ごとに「n 件を発注済にする」。チェックを外した行は発注しない
- 仕入先が空の商品は「仕入先未設定」にまとめる
- **入荷待ち**: 発注済の一覧。「入荷」を押すと入荷数(初期値=発注数)を確認して確定。`receive_purchase_order` を呼ぶ
- 入荷待ちの行から取消できる。入荷済は取消不可
- 候補に無い商品を手動で追加できる
- 発注者・入荷担当者は端末に記憶した担当者名
- 候補が 0 件で発注点未設定の商品があるときは、`/items/setup` への案内を出す
- 発注は経費に計上しない

### `/waste` 廃棄
- 動きは既存のまま(営業日の扱い、直近48時間の削除制限を含む)。見た目と下タブだけ合わせる

### `/more` その他
- 商品管理、一括設定、履歴、廃棄、担当者名の変更、経営ダッシュボード(店長ログイン)へのリンク

### `/items` 商品管理
- 選択中の店舗の商品の登録・編集・削除。項目は既存どおり(名前、カテゴリ、単位、在庫、発注点、適正、単価、仕入先、メモ)
- 仕入先は既存の仕入先から候補を出す(表記ゆれ防止)
- 削除は既存どおり店長ログインが必要。発注・棚卸の履歴がある商品は削除できず、その旨を表示する

### `/items/setup` 一括設定
- 選択中の店舗の商品を一覧にし、各行で **発注点・適正在庫・仕入先** をその場で入力できる
- 「未設定だけ表示」の切替(初期値オン)。カテゴリ切替あり
- Enter / 次へ で次の行の同じ項目へ移る(63 件を連続入力できること)
- 仕入先は既存値から候補を出す
- 変更行だけをまとめて保存。失敗時の扱いは在庫チェックと同じ
- 在庫数はここでは変えない(`stock_logs` に残らない変更を作らない)
